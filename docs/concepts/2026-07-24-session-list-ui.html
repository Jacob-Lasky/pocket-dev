Five sessions, one glance

Today, finding the session that needs you means tmux → Next → read the screen → repeat. This replaces that with the thing your phone already does well for five conversations: a list. Tap a row to try it — opening a session marks it read, which is the one piece of state the transcript can't tell you.

    The three states

    Working
    Claude is mid-turn, a tool call in flight.
    transcript → busy
    Waiting on you
    It finished, and you haven't looked yet.
    transcript → idle + unread
    Read
    It finished and you've seen it. Quiet.
    transcript → idle + read

    Where the state comes from

    Two of the three are already built. classifyTranscript from PR #18 reads the transcript tail and returns busy or idle, which is the working-versus-finished split.

    The catch: “waiting on you” and “read” are the same transcript state. Nothing in the JSONL knows whether you've looked. That axis is client-side bookkeeping, last-viewed against last-output, layered on top of the two states the server can see.

    Choices made here

    Rows, not cards. Full-bleed with hairline rules, like the app's existing toolbar. Cards would add chrome without adding information.

    Unread reads as weight, not colour. A brighter, heavier title plus one dot on the right. The status pill already carries colour; doubling up would make five rows shout at once.

    Kill moved inside the session. Destructive actions don't belong on a list you scan one-handed. It lives next to the thing it destroys.

    The title is the conversation's own. Every row is Claude's aiTitle, the same name the resume picker shows, with the last prompt beneath it (issue #20).

    Still open

    Does the list replace the tab strip or sit beside it? Where does read/unread persist when a phone and a desktop disagree? Does “unread” mean any output, or only a finished turn? Those are the questions in #21 that this mockup deliberately doesn't answer.
